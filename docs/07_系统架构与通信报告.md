## 1. 系统总览

这是一个 **ROS 2 Humble + Gazebo Classic + MoveIt 2 / MTC** 的仿真分拣系统。

核心数据流：

```text
文本/语音（可选）
      │
      ▼
classify_agent
      │  RobotCommand（/classify/command）
      ▼
classify_task（C++ 状态机 + MoveIt Task Constructor）
      │
      ├── 读取 /classify/scene_status、/classify/detections、/joint_states
      ├── 调用 MoveIt /get_planning_scene、/move_group action
      ├── 调用 Gazebo /gazebo/get_entity_state
      ├── 发布 /classify/status、/classify/result
      │
      ▼
Gazebo Classic（Piper + 夹爪 + RGB-D + 物块）
      │  /camera/color/image_raw、/camera/native/depth/image_raw
      ▼
gemini335_registration（D2C 对齐）
      │  /camera/depth/image_raw + CameraInfo
      ▼
detect_blocks（颜色分割 + 三维定位）
      │  /classify/detections
      ▼
scene_bridge（ID 跟踪、场景校验、MoveIt 场景同步）
      │  /classify/scene_status
      └──► MoveIt PlanningScene
```

设计原则：

1. **World 是场景几何的唯一来源**，Gazebo 和 MoveIt 场景桥读取同一份 SDF。
2. **视觉只提供测量，不直接控制运动**；所有运动由 `classify_task` 通过 MoveIt/MTC 执行。
3. **语言层只输出高层意图**，不接触关节角或任意坐标。
4. **失败要显式暴露**：视觉过期、夹持失败、放置越界都会进入 `FAILED` 或保持 `LAST_SEEN`，不会静默继续。

## 2. 启动链路

### 2.1 一键启动

`scripts/run_classify.sh` 最终执行：

```bash
ros2 launch classify_bringup classify.launch.py \
  gui:=<bool> rviz:=<bool> auto_start:=<bool> plan_only:=<bool> \
  world:=<path> depth_noise_stddev_m:=<float> \
  depth_dropout_probability:=<float> stress_seed:=<int>
```

`classify.launch.py` 依次包含四个 launch：

```text
classify.launch.py
├── classify_description/gazebo.launch.py
│   ├── gazebo（server + 可选 gui）
│   ├── gemini335_registration（align_rgbd）
│   ├── robot_state_publisher
│   ├── spawn_piper（spawn_entity.py，一次性）
│   ├── spawner_piper_joint_state_broadcaster（一次性）
│   ├── spawner_piper_arm_controller（一次性）
│   ├── spawner_piper_gripper_controller（一次性）
│   └── rviz2（可选，使用 piper.rviz）
│
├── classify_moveit_config/move_group.launch.py
│   ├── move_group
│   ├── scene_bridge
│   └── moveit_rviz（可选，使用 moveit.rviz）
│
├── classify_perception/perception.launch.py
│   └── detect_blocks
│
└── classify_task/task.launch.py
    └── classify_task
```

`task.launch.py` 会：

- 用 `MoveItConfigsBuilder` 加载 `classify_moveit_config`；
- 用 `workcell_config.py` 解析当前 world，得到 `expected_red_count`、`expected_green_count`、`expected_blue_count` 和固定设施碰撞盒；
- 把 `task.yaml`、world 统计值和 `use_sim_time` 一起传给 `classify_task`。

所有节点都使用 `use_sim_time=true`，时间基准来自 Gazebo 的 `/clock`。

### 2.2 启动顺序中的关键点

1. `classify_description` 必须先构建并生成 `piper_sim.urdf`。
2. `spawn_piper` 从 `/robot_description` 话题读取 URDF；`robot_state_publisher` 与 Gazebo 使用同一份描述。
3. 三个 controller spawner 挂在 `spawn_entity` 退出事件之后，确保 `/controller_manager` 已就绪。
4. `scene_bridge` 与 `move_group` 同时启动；场景桥会等待 `/get_planning_scene`、`/apply_planning_scene` 可用。
5. 感知与任务节点可以在场景稳定前启动，它们会持续等待 `VISION_READY`。

## 5. 频率与时间特性

### 5.1 频率汇总

| 项目 | 频率/周期 | 来源 |
|---|---|---|
| RGB/深度相机 | 15 Hz | `gemini335.yaml` 中 `fps: 15` |
| D2C 对齐 | 每对 RGB-D 一次，约 15 Hz | `align_rgbd.cpp` 精确时间同步 |
| 感知检测发布 | **上限 5 Hz**（相邻处理至少间隔 0.2 s） | `detect_blocks.cpp` |
| 感知 watchdog | 300 ms | `detect_blocks.cpp` |
| 场景状态发布 | 250 ms，即 4 Hz；检测到达时额外立即发布 | `scene_bridge.cpp` |
| 任务状态发布 | 200 ms，即 5 Hz；阶段切换立即发布 | `classify_task.cpp` |
| 关节状态 | 50 Hz | `ros2_controllers.yaml` |
| 控制器更新 | 100 Hz | `ros2_controllers.yaml` |
| 控制器 action 监控 | 20 Hz | `ros2_controllers.yaml` |
| 夹持状态发布 | 持物时每 100 ms，即 10 Hz | `contact_grasp.cpp` |
| TF 动态发布 | 随 `/joint_states`，约 50 Hz | `robot_state_publisher` |
| 语言 agent 轮询 | 100 ms（等待终态） | `agent_node.py` |
| 语音录音 | 每次 4 s | `agent_node.py` / `voice_command_node.py` |

### 5.2 视觉有效性与稳定性

| 参数 | 值 | 含义 |
|---|---|---|
| 检测数据有效窗口 | 0.8 s | 超过后场景桥/任务视为过期 |
| 相机静止判定 | 线速度 <0.015 m/s，角速度 <0.05 rad/s | `detect_blocks` |
| 相机稳定等待 | 0.4 s | 运动后需静止 0.4 s 才处理 |
| 相机运动平滑间隔 | 最小 0.2 s | 感知实际最高 5 Hz |
| RGB-D 同步容差 | 默认 0.0（精确）；可设 0..33 ms | `sync_tolerance` |
| 视觉超时 | 20 s | 任务等待单个对象的新鲜视觉 |
| 场景跟踪确认 | 连续 3 次、累计 ≥0.35 s | 位置差 <3 mm、yaw 差 <0.025 rad |
| 目标关联半径 | 45 mm | 最近邻匹配 |
| 关联歧义判据 | 次优与最优差 <10 mm → 拒绝 | 防止同色身份交换 |

### 5.3 任务与规划时间

| 参数 | 值 | 含义 |
|---|---|---|
| 单件 MTC 规划超时 | 30 s | `planning_timeout` |
| 单个 MoveTo 阶段超时 | 8 s | `add_move` / `add_pose` |
| 规划尝试次数 | 1 | `task->plan(1)` |
| 速度缩放 | 0.20 | `velocity_scaling` |
| 加速度缩放 | 0.15 | `acceleration_scaling` |
| 笛卡尔步长 | 3 mm | `CartesianPath::setStepSize` |
| 笛卡尔最小完成比例 | 1.0 | 不允许部分轨迹 |
| 笛卡尔跳变阈值 | 10.0 rad | `cartesian_jump_threshold` |
| 夹持等待 | 1.5 s | 等待 Gazebo 接触约束建立 |
| 放置稳定等待 | 1.5 s | 等待物块落稳后再测量 |
| 单次基线任务耗时 | 约 80–90 s | 历史验收记录 |
| 五块任务耗时 | 约 3 min | 历史验收记录 |

## 8. 感知链路细节

### 8.1 D2C（`gemini335_registration`）

- 输入：`/camera/color/image_raw`、`/camera/native/depth/image_raw`。
- 同步：`ExactTime`，队列 30；要求 RGB 与深度时间戳完全一致、尺寸一致、深度编码为 `32FC1`。
- 参数来自 `gemini335.yaml`：
  - RGB：640×480、15 fps、`fx=457.007`、`fy=461.036`、`cx=320`、`cy=240`；
  - 深度：640×480、15 fps、`fx=fy=372`、`cx=320`、`cy=240`、`min_z=0.17 m`；
  - RGB 光心相对深度光心：`(14, 0, 2.02) mm`；
  - 基线 50 mm。
- 输出：
  - 对齐深度 `/camera/depth/image_raw`，`16UC1` 毫米，frame 使用 RGB 光学系；
  - `/camera/color/camera_info`、`/camera/depth/camera_info` 使用 RGB 内参；
  - `/camera/native/depth/camera_info` 使用原生深度内参；
  - 旧话题 `/wrist_depth_sensor/*`。
- 可选深度压力：`depth_noise_stddev_m`、`depth_dropout_probability`、`stress_seed`，默认关闭。

### 8.2 检测（`detect_blocks`）

- 输入：RGB、对齐深度、RGB CameraInfo。
- 同步：默认 `ExactTime`（队列 20）；`sync_tolerance>0` 时切换为 `ApproximateTime`，上限 33 ms。
- 前置检查：
  - 三路 frame_id 一致且等于 `camera_color_optical_frame`；
  - 图像尺寸与 CameraInfo 一致；
  - 深度编码为 `32FC1` 或 `16UC1`；
  - 畸变模型为 `plumb_bob` 或 `rational_polynomial`；
  - 图像时刻的 `base_link ← camera_color_optical_frame` TF 可用。
- 相机稳定性：线速度阈值 0.015 m/s、角速度阈值 0.05 rad/s；运动后需静止 0.4 s。
- 处理节流：相邻处理至少间隔 0.2 s，因此最高 5 Hz。
- 颜色阈值（HSV）：

| 颜色 | H | S | V |
|---|---|---|---|
| 红 | 0–12 或 170–179 | 80–255 | 50–255 |
| 绿 | 35–90 | 80–255 | 50–255 |
| 蓝 | 95–135 | 80–255 | 50–255 |

- 后处理：3×3 开运算；轮廓面积 ≥100 px；轮廓不能贴图像边界；深度有效范围 0.05–2.0 m。
- 取料区（来自 `workcell.yaml`）：`x ∈ (0.30, 0.55)`、`|y| < 0.20`、`z` 在桌面顶面附近。
- 将像素按去畸变射线投影到相机系，再用图像时刻 TF 转到 `base_link`，最后拟合顶面并估计中心、尺寸、yaw、置信度。
- 输出 `/classify/detections` 与 `/classify/detection_markers`。
- 无有效帧时，watchdog（300 ms）发布 `camera_stable=false` 的空消息。

### 8.3 场景桥（`scene_bridge`）

- 订阅 `/classify/detections`，执行严格测量校验：
  - 位置在取料区；
  - `|z - (table_top_z + cube/2)| ≤ 7 mm`；
  - `|top_z - center.z - cube/2| ≤ 2 mm`；
  - 置信度 ≥0.75；
  - 顶面宽/深在 50 mm 的 88%–112%；
  - 平面误差 ≤3 mm；
  - 可见点 ≥150。
- 视觉 ID 跟踪：
  - 新目标需连续 3 次一致观测、累计 ≥0.35 s 才确认；
  - 位置一致性 3 mm、yaw 一致性 0.025 rad；
  - 最近邻关联半径 45 mm；若次优与最优差 <10 mm，判定歧义并拒绝该观测；
  - 新鲜窗口 0.8 s。
- 场景就绪 `ready`：
  - 相机稳定且最近数据 <0.8 s；
  - 每种颜色数量符合 world 统计；
  - 每个期望对象要么新鲜、要么已放置；
  - 没有多余工件。
- 将固定设施（桌面、桌腿、红/蓝盒、障碍）和确认方块同步到 MoveIt PlanningScene。
- 发布 `/classify/scene_status`（4 Hz 定时 + 更新即发）和 `/classify/scene_markers`。
- 已放置对象继续保留在场景中，标记为 `PLACED`；过期对象标记为 `LAST_SEEN`。

## 9. 场景桥与任务状态机

### 9.1 任务状态

```text
IDLE
  │ /classify/start 或 /classify/command
  ▼
DETECTING ──► PLANNING ──► PICKING ──► PLACING ──► DONE
  │                            │
  │                            └── pick_hold ──► HOLDING
  └── 失败/取消 ──► FAILED / CANCELLED
```

- `DONE` 后若仍有新鲜工件，可以接受下一条语言指令。
- `HOLDING` 或 `held_object` 非空时，`/classify/start` 会被拒绝，必须先重置。
- `FAILED` / `CANCELLED` 后同样需要重置再重试。

### 9.2 典型 MTC 阶段序列

放置模式：

```text
confirmed scene
open gripper
move above object
approach object
allow finger contact
close gripper
attach object
lift object
carry above bin
lower above bin
release gripper
detach object
settle in bin
restore finger collision
retreat from bin
return home
```

`pick_hold` 模式在 `lift object` 后结束，进入 `HOLDING`。

`home` 指令只规划/执行回 HOME，不操作工件。

### 9.3 物理校验

| 检查 | 判据 |
|---|---|
| 夹持绑定 | 1.5 s 内收到 `held_object`，且模型名匹配颜色前缀 |
| 夹持位置 | Gazebo 实测位置与视觉目标差 ≤10 mm |
| 抬升成功 | z 上升 ≥0.7×lift，水平偏移 ≤30 mm |
| 放置成功 | x/y 偏差 ≤27 mm，z 偏差 ≤12 mm |
| 盒内约束 | 物块完整位于盒内，不穿墙/穿底 |
| 方块间距 | 满足 `separated()` 的最小间距 |
| 绿块参考 | 整批前后位移 ≤2 mm |

## 12. 常见问题排查

| 现象 | 可能原因 | 检查/处理 |
|---|---|---|
| 没有 `/classify_task` | 构建缺失或 launch 失败 | 查看终端日志；确认 `colcon build` 成功 |
| `/camera/color/image_raw` 无数据 | Gazebo 相机未渲染/无显示上下文 | 检查 `DISPLAY`，运行 `bash doctor.sh`；`--headless` 仍需渲染上下文 |
| `/camera/depth/image_raw` 无数据 | D2C 精确同步失败或 frame 不匹配 | 检查 `/camera/native/depth/image_raw` 与 RGB 时间戳、frame_id |
| `VISION_UNAVAILABLE` | 相机移动、数据过期、目标未确认 | 等 0.4 s 静止；检查 `/classify/detections` 与 TF |
| `scene_ready` 返回 false | 数量不符、目标 stale、额外工件 | 看 `detail` 与 `stale_colors`；确认 world 与期望数量一致 |
| MTC 规划失败 | MoveIt 场景缺失、IK 不可达、碰撞 | 检查 `move_group` 日志、`/get_planning_scene`、HOME 与 TCP |
| 夹持后无 `held_object` | 双指未同时接触、接触时间 <50 ms | 检查夹爪开合、`/classify/grasped_object`、物理参数 |
| `/joint_states` 无数据 | spawner 未激活 | 检查 `controller_manager` 和三个 spawner 日志 |
| 两套仿真互相干扰 | 同一 `ROS_DOMAIN_ID` 已有 controller manager | `bash scripts/stop_classify.sh` 后重启 |
| SSH 下 GUI 不显示 | DISPLAY/XAUTHORITY 未继承 | `source scripts/tools/runtime_env.sh`；见 doctor 说明 |
| `piper_sim.urdf` 不存在 | 未执行生成脚本 | 先构建描述包，再 `bash scripts/tools/build_urdf.sh` |

## 13. 已知限制与注意事项

1. **仅仿真**：没有真机 CAN 执行后端；夹持为理想固定约束，不代表真实摩擦/夹持力。
2. **相机参数非单位实测**：内参与手眼来自官方标称值/已有真机项目，不能作为实机精度结论。
3. **视觉适用面窄**：只验证 50 mm 方块和已验证布局；不保证任意形状、任意 yaw、未知动态障碍或同色遮挡。
4. **深度压力是测试输入**：`--sensor-stress` 的噪声/缺失不是 Gemini 335 实测模型。
5. **`--plan-only` 不是抓放验收**：只验证规划，不移动物块。
6. **重置方式**：优先 `bash scripts/reset_classify.sh`。独立语音节点的 `/reset_simulation` 类型与 Gazebo 不一致（Trigger vs Empty）。
7. **生成 URDF 不入库**：`piper_sim.urdf` / `piper_sim_rviz.urdf` 含工作区绝对路径；移动工作区后必须重新生成。
8. **ROS_DOMAIN_ID**：脚本默认 42；所有终端必须一致，否则节点互相不可见。
9. **密钥安全**：语言/语音节点的 API key 只从 `DEEPSEEK_API_KEY` 环境变量读取，禁止写入源码或提交到仓库。
10. **日志安全**：`build/`、`install/`、`log/` 可能包含环境变量和密钥，禁止上传或打包分享。
