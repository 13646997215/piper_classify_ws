## 1. 任务原始要求

来源：课程 PPT《A1 工件分类搬运》（工业场景：产线末端的分类与装箱）

| 项目 | 要求 |
|---|---|
| 标题 | A1 工件分类搬运 |
| 工业场景 | 产线末端的分类与装箱 |
| 基础任务 | 将 **3 个工件**按给定类别，放入**两个指定料区**（本实现用 2 个料盒） |
| 参考 | MoveIt Task Constructor 抓取放置示例 |
| ROS 应用点 | ① 任务指令 ② 运动接口 ③ 夹爪状态 ④ 完成数量反馈 |
| 可选扩展 | ① 用相机识别颜色 ② 处理抓取失败 |
| **最低演示** | **连续搬运 3 个工件并显示结果** |

### 1.1 本实现的范围裁定

- **当前只在仿真执行**；2026-10-01 用户追加要求：参考 Gemini 335 官方数据及 toy_pick_ws 保存的手眼矩阵减小真机与仿真差异，未授权本轮运行真实机械臂。
- 分类判据采用**颜色**（命中"相机识别颜色"扩展项）。
- 视觉抓取**必须是真实视觉链路**（相机图像 → 检测 → 三维坐标），**不接受硬编码绝对坐标**。
- 机器人描述 / MoveIt 配置 / 仿真 world **以官方开源资料为准**，不套用其他整机项目。
- 节点程序**全部 C++**（`ament_cmake`），Python 用于 launch、配置导入和验证工具。

### 4.2 夹爪几何（自行解析二进制 STL 得到）

| 网格 | 面数 | 包围盒 min | 包围盒 max |
|---|---|---|---|
| `gripper_base.STL` | 12988 | [−0.04, −0.0725, 0] | [0.0305, 0.0725, 0.063] |
| `link7.STL` | 2086 | [−0.028, −0.0765, 0] | [0.028, 0, 0.0265] |
| `link8.STL` | 2086 | 同上（同一网格，靠 rpy 镜像） | |

推导结论：

- 夹爪两指**镜像**：j7 正向 → 手指向 −Y 移；j8 负向 → 手指向 +Y 移。
- **全开** = `(j7=0.035, j8=−0.035)` → 开口 **70 mm**（夹 `joint7` 真实范围 0~0.035 ×2）。
- **全闭** = `(j7=0, j8=0)` → 两指网格原点**完全重合** → 需留微小间隙，取 `0.0005 / −0.0005`。
- **历史 TCP 估计 0.135 m 已被替代**：现行任务使用法兰 +Z 方向 **0.132 m**，依据当前碰撞指形和桌面净空设计；不是实机工具标定值。
- 夹爪**开合方向** = 夹爪基座的 **Y 轴** → 抓取时物体宽度方向须对齐 link6 的 Y。
- 夹爪伸出方向 = **`link6` 的 +Z**（与 toy_pick_ws 的 `grasp_config.py` 注释「link6 +Z 为接近轴」一致）。
- `link7.STL` 与 `link8.STL` 顶点数完全相同 → 同一网格，镜像仅靠 joint8 的 rpy。
- 所有 URDF **均无 `scale=`**，网格本身已是米制。

### 4.3 历史工作空间可达性估算（2026-09-29，未通过接管复核）

FK 实现与 `toy_pick_ws/src/perception/toy_grasp/toy_grasp/piper_fk.py`（已与松灵官方改进 DH 交叉验证，误差 <0.2 mm）逐式一致。

**垂直向下抓取（link6 +Z 朝下）精确 IK 可行性**（r = 到基座水平距离）：

| TCP 高度 z \ r | 0.15 | 0.20 | 0.25 | 0.30 | 0.35 | 0.40 |
|---|---|---|---|---|---|---|
| −0.30 ~ +0.25 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 |
| +0.30 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 |
| +0.40 | 4/4 | 4/4 | 3/4 | 4/4 | 4/4 | 4/4 |

（每格 = 4 个不同 yaw 方位（30°/120°/210°/300°）中有几个 IK 收敛，容差：位置 8 mm、姿态 3°）

**旧结论“整个工作带任意方位都可垂直向下抓取”现已撤回。** 接管时发现后续 `check_ik.py` 将世界 z 当作基座 z，并把实际 180° 的姿态差误报为 0°。独立复算仅证明三个物块中心存在满足限位的垂直姿态数值解；料盒放置、碰撞、接近轨迹及真实执行均未验证。见 [06_接管审查.md](06_接管审查.md) 第 4 节。

整体可达范围（不限姿态）：x ∈ [−0.72, 0.73]，y ∈ [−0.73, 0.73]，z ∈ [−0.35, 0.85]。

现行 HOME 关节参考为 `[0, 0.87266, −1.22173, 0, 1.22, 0]` rad；按现行 URDF 复算，TCP 在 **base_link 系**约 `(0.226, 0, 0.330)`，`link6` 的 +Z 约 `(0.708, 0, −0.706)`。世界系 TCP 的 z 需再加基座高度 0.347 m。

## 6. 视觉链路可行性依据

- `libgazebo_ros_camera.so` 配合 `<sensor type="depth">` 可发布：
  - `image_raw`（RGB）
  - `depth/image_raw`（深度，`sensor_msgs/Image`，编码 `32FC1`）
  - `camera_info`
  - `points`（点云）
- `libgazebo_ros_depth_camera.so` **不存在**，但**不需要**。
- C++ 依赖齐备：`cv_bridge` 3.2.1、OpenCV 4.5.4、`tf2_ros`、`tf2_eigen`、`image_transport`。
- `vision_msgs` **未安装**；已建立自定义 `classify_interfaces/msg/DetectedBlock.msg` 和 `DetectedBlocks.msg`。

**2026-09-30 视觉历史事实**（旧相机模型）：Gazebo 腕部 RGB、深度、CameraInfo 已实际发布，消息统一使用 `camera_optical_frame`。C++ `classify_perception` 已通过 HSV、深度反投影、按图像时间查询 TF 与 `base_link` 三维取料区筛掉红/蓝料盒，发布三件物块的中心位置和 RViz 标记。图像中料盒轮廓比同色物块大，不能按最大轮廓取目标。物块位姿必须来自图像；取料区范围和 50 mm 立方体厚度是场景配置。用户当前只搬红、蓝两件，绿块仅作为视觉校验。


## 2026-09-30 追加事实 · 移动腕部相机的定位误差
